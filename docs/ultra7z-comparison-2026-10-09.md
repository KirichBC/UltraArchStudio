В этом единственном прогоне UltraArch затратил на 40,65% меньше времени, но результат на 9,35% больше результата Ultra7z; пик выделенной памяти на 7,64% выше. Значит, преимущество UltraArch по качеству сжатия и низкому потреблению памяти не достигнуто. Это не доказательство общего превосходства по скорости: стратегии поиска и версии backend различаются, кэш сохраняется, порядок запуска фиксирован. Один прогон не оценивает разброс.

UltraArch завершил все 53 кандидата без ошибок. Лидер: `LZMA2 384MB Solid 128m`, `-m0=lzma2:d393216k:fb273:lc3:lp0:pb2 -ms=128m -mx=9 -mmt=2`. Итоговая машинная сводка — `validation/ultra7z-comparison-2026-10-08-no-ttf/comparison.json`.

Вход `F:\Test.7z`: 434 024 549 байт, SHA-256 `530b3e4d6377b154bc8313ebc3b9be00f50376390c5f27ead3a678059259cea7`. Для UltraArch сохранена идентичная копия. Состав эталона: 10 144 файла, 890 папок. TTF исключены пользователем после повторяемой остановки Ultra7z на группе шрифтов. Этот набор отличается от предыдущих тестов.

Ultra7z 1.15: Extreme2, LZMA 512 МиБ / fb273, PPMd 1024 МиБ / order32, 4 задачи, brute force LZMA включён, уровень 5 (сэмплы 25 МиБ по уточнению пользователя), все группы Delta, No PPMd >80 МиБ, большие страницы запрошены, создание нового архива. Исходный solid-архив имеет непрерывный блок; размер выборки brute force не равен размеру solid-блока. Использованный backend: `res/7z24/7z.exe`, 7-Zip 24.08. При отдельных вариантах программа меняет словари и число потоков относительно настроек GUI.

Результат `F:\Test_optimized.7z`: **367 383 626 байт**, SHA-256 `91efe13d53be0776871a00c68c5ccb6e924878e0aaa02c10e709d8664664bb1c`. Экономия **66 640 923 байта / 15,354%**. GUI сообщает 2850 с (47 мин 30 с), строка результата 2849 с; наблюдаемый секундным монитором интервал активности потомков 2848,021 с. Эти границы времени согласуются в пределах точности наблюдения, но не являются одним и тем же измерителем.

Пик committed memory дерева Ultra7z: **22 846 214 144 байт / 21,28 ГиБ**; отдельного процесса: 5 703 806 976 байт. Это выделенная память, не физический рабочий набор. Фактическое применение больших страниц не установлено. CPU и transfer counters включают время GUI до/после обработки; для точного интервала следует использовать записи samples. Внешний Job Object ограничивал дерево 26 624 МиБ, без завершения GUI при закрытии монитора.

Независимый 7-Zip 26.03 выполнил test и распаковку результата. Совпали набор путей, размеры и SHA-256 всех 10 144 файлов и состав 890 папок. SHA исходного архива после оптимизации совпал с сохранённой копией. Дополнительная проверка не включается во время оптимизации.

Двухсекундный опрос команд не охватывает короткие процессы. Дополнительно включена ETW-трасса ProcessThread через WPR без CPU sampling и stack capture. Она начата после начала прогона; ранние события не восстановлены. На остановке WPR: Dropped event 0, Events Lost 0. Из трассы выделено 16 172 события, содержащие имена 7z/Ultra7z и поля CommandLine; это число событий, не уникальных кандидатов. Tracerpt сообщил о событиях вне схемы, поэтому полнота всех остальных полей не утверждается. Сырые ETL/XML включают системные процессы; выделенный JSONL содержит только подходящие события, а не весь системный журнал.
