# Исправления UltraArch Studio 2.1 — 2026-10-04

> Исторический документ. Актуальные файлы и сборка описаны в [главном README](../../README.md).

Проект приведён к Windows 10/11 x64. Исходный аудит: `docs/history/2026-10-04-audit.md`. Это отчёт о найденных и исправленных проблемах, а не утверждение об отсутствии любых возможных дефектов.

## Исправления

1. **Сохранность результата.** Финальный выход формируется в staging-каталоге рядом с целевым файлом. До публикации проверяются статус процесса, тест архива, manifest, полная контрольная распаковка и контрольные суммы. Проверка совпадения Windows-путей учитывает регистр Unicode через CompareStringOrdinal, предотвращая перезапись входного файла под другим написанием имени. Неудача сохраняет прежний выход; тома учитываются как набор файлов. Исключения UI callbacks не вызывают откат уже опубликованного архива.
2. **Корректный итог запуска.** Введено состояние Failed. CLI возвращает успех только после публикации и сообщает фактические выходные файлы. Убрана зависимость проверки от англоязычного текста `Everything is Ok`.
3. **Память и процессы Windows.** Исправлены GiB/MiB в GUI, общий Job Object с JOB_MEMORY/PROCESS_MEMORY, проверка подключения защиты, резервирование оценок памяти в очереди, независимые токены отмены, дерево процессов под отдельным Job Object и тайм-ауты. CreateProcessW получает явный путь, корректное экранирование и ограниченный список наследуемых handles. Вывод ограничен по памяти; телеметрия показывает committed memory и I/O дочерних процессов.
4. **Потоки и закрытие GUI.** Настройки фиксируются на запуск. Медленные процессы выполняются вне mutex результатов. GUI читает состояние на основном потоке, callbacks отписываются после cancel/join. Исправлены гонки pause/resume с финализацией и завершение при паузе. Незапущенные после остановки задачи помечаются Skipped.
5. **PE-парсер.** Убраны переполнение offset и невыровненное чтение. Проверяются границы и архитектура перед выбором x86-фильтров. Недоступные файлы/символические ссылки дают диагностируемую ошибку.
6. **Матрица сжатия.** Сохранены Store и базовые LZMA2 независимо от энтропии. Маленькие файлы получают работающую матрицу. Словари ограничены объёмом данных и бюджетом памяти; PPMd и четыре потока BCJ2 учитываются отдельно. Исправлены BCJ2 bindings и синтаксис `mf=bt5`; варианты проверяются реальным 7-Zip. CPU-настройки учитывают число workers и физические ядра.
7. **Настройки выхода.** Solid, пароль и шифрование заголовков входят в параметры кандидата. Тома и SFX пересобираются; SFX+тома отклоняются. Существующие тома резервируются и восстанавливаются при обрабатываемой ошибке.
8. **Предобработка и временные файлы.** Workspace создаётся до распаковки/Leanify/ECT. Архивируется результат успешных этапов предобработки, исходники не меняются. Неудачные и увеличивающие размер этапы отбрасываются. Убраны фиктивные Precomp/SREP без обратного восстановления. При успехе workspace очищается; проверенный лидер отменённой/ошибочной сессии сохраняется для resume.
9. **Resume.** Версионированный checkpoint содержит результаты, лидера, параметры и workspace. Fingerprint учитывает полное содержимое входа, пустые каталоги, настройки и используемые файлы инструментов, включая 7z.dll. Восстанавливается проверенный архив, завершённые совместимые задачи исключаются из очереди. Запись сериализована и атомарна; повреждённые/устаревшие checkpoint игнорируются.
10. **Пресеты и секреты.** nlohmann/json заменяет ручную сборку/парсинг JSON. Исправлены встроенные пресеты, escaping, Unicode, диапазоны и недопустимые имена файлов. Пароли не сохраняются и не отображаются в результатах/экспорте. CSV корректно экранирует поля. Пароль всё ещё передаётся внешнему компрессору через аргументы процесса.
11. **GUI.** Исправлены выбор входной папки, диалог сохранения нового файла, автоматическое расширение SFX, Ctrl+S/Space/Escape, отображение настоящих выходных файлов и работа обновлений при сворачивании. Выключение вызывает системный shutdown.exe по явному пути и может быть отменено кнопкой. Убраны пункты меню выбора победителя/повторного теста без реализации. Пояснена семантика предобработки.
12. **Сборка.** Общее ядро вынесено в static target. GUI собирается только для Windows. MSVC Debug/Release используют правильный runtime; MinGW toolchain не содержит локальных абсолютных путей. Добавлены Windows CI, CTest integration suite, упаковка в новый каталог, тестовые EXE и checksum manifest. README описывает реализацию вместо прежних неподтверждённых обещаний. Включены тексты лицензий основных зависимостей.

## Проверка

- Native Debug: 19 внутренних unit-тестов, suite прошла.
- Native integration: 11 выполняемых сценариев с настоящим 7zz 26.03. Отдельный сценарий SFX помечается пропущенным вне Windows. Проверены маленькие BMP, повторяющиеся случайные блоки, Unicode, пароль с кавычками/пробелами/backslash, тома, пустые каталоги, solid, repack, сохранение прежнего выхода, отмена/resume, изменение входа, все варианты Deep-матрицы, параллельное завершение во время паузы, неверное содержимое валидного архива, исключения callbacks, тайм-аут/отмена процесса и использование обработанной копии.
- Обе suites повторно прошли под AddressSanitizer + UndefinedBehaviorSanitizer: 14.46 секунды, ошибок санитайзеров не обнаружено. Native Debug: 11.11 секунды.
- Windows x64 Release GUI и оба тестовых EXE успешно собраны MinGW GCC 16.1. Проверена таблица импортов приложения: нет DLL MinGW runtime, используются системные DLL Windows. Фактический запуск Windows GUI, SFX, WinAPI Job Objects/OOM и MSVC CI на этом macOS-хосте не выполнялся. Для проверки на Windows пакет содержит `tools/windows-smoke.ps1` и тестовые EXE; workflow также запускает их на Windows.

- Дополнительно прошли CLI-проверки: справка, шесть неверных комбинаций/значений аргументов, What-if с маскированием пароля, реальное сжатие Unicode-входа в новый выходной каталог и код 1 при ошибке финализации. Windows manifest разобран как корректный XML.

## Практические ограничения

- Финальная распаковка требует места под полный набор данных; проверки свободного места не являются резервированием диска. Для архивов неизвестного распакованного размера исчерпание места всё ещё возможно, но выход не публикуется при ошибке.
- Набор томов нельзя заменить одной атомарной файловой операцией. При аварийном выключении во время публикации резервные копии могут потребовать ручного восстановления из `.ultraarch-output-*/backup`.
- Контрольные суммы входа — FNV-1a 64 для обнаружения изменений, не криптографическое подтверждение подлинности. SHA-256 manifest пакета идентифицирует файлы и не заменяет подпись издателя.
- Windows-утилиты из исходного `bin` сохранены. Их происхождение/подписи и все транзитивные лицензии конкретных бинарных сборок не подтверждались; основные upstream notices и ссылки на исходники включены в THIRD_PARTY.md.
- Safe использует стандартные кодеки, но совместимость с конкретными версиями WinRAR не проверялась. Полный поиск глобального оптимума не гарантируется, особенно при включённом adaptive.
- Предобработка меняет архивируемые ресурсы. Побайтовая идентичность исходным файлам обеспечивается режимом без предобработки в рамках проверяемых файлов; NTFS ACL, alternate data streams и специальные файловые объекты этим manifest не проверяются.
- GUI What-if для архивов предлагает использовать CLI; для путей длиннее буфера GUI нужен CLI. На многогрупповых CPU принудительная affinity отключена.

## Артефакты

Актуальная сборка: `release-fixed/UltraArchStudio_Win64/UltraArchStudio.exe`, portable ZIP рядом. Старый `release/` не изменён. Копия исходников до исправлений сохранена в `/private/tmp/ultraarch-before-fixes` на этой машине; временный каталог не заменяет систему контроля версий.
