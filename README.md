# UltraArch Studio

> В этом репозитории представлены исходный код и зависимости для сборки. Локальные готовые сборки (`release/`) и результаты проверок (`validation/`), упоминаемые ниже и в документации, сюда не включены.

Оптимизатор и репакер архивов для **Windows 10/11 x64**. C++20, Dear ImGui. Программа сравнивает реальные результаты 7-Zip и сохраняет наименьший успешный архив; при одинаковом размере выбирает более быстрый вариант.

## Навигация по проекту

- `src/` — исходники приложения, ядра и интерфейса; `tests/` — автоматические проверки.
- `bin/` — внешние утилиты и кодеки; `vendor/` — библиотеки; `licenses/` — лицензии.
- `resources/` — значок и Windows-манифесты; `presets/` — пресеты.
- `tools/` — сборка, упаковка, smoke-проверка и benchmark.
- `cmake/toolchains/` — конфигурации компиляторов; `build/` создаётся при локальной сборке.
- [Документация](docs/README.md) — инструкции, план, состояние реализации и история разработки.
- [Единый план доводки](docs/implementation-plan.md) — общий план исправлений, RAM/CPU-планирования, RAM-транспорта, поиска и упрощения интерфейса.
В распакованном portable ZIP запускайте `UltraArchStudio.exe` из его корня; переносите пакет целиком. Фактические проверки и ограничения этой сборки: [реализация Photoshop postrun](docs/photoshop-postrun-implementation-2026-10-11.md). 
## Работа с данными

- Вход: отдельный файл, папка или распознаваемый по сигнатуре архив ZIP, RAR, 7z, gzip, tar. Архив сначала распаковывается во временный каталог. Для томов входом служит первый том `.001`.
- Выход: `.7z`, тома `.7z.001` и далее либо SFX `.exe`. SFX и тома одновременно не поддерживаются. Для SFX нужен `bin/7z.sfx`.
- Все кандидаты получают пароль, шифрование заголовков и пользовательский solid. Готовый результат переиспользуется при публикации, разбиении на тома и добавлении SFX; выбранные solid-блоки и методы сохраняются.
- Режим Disk по умолчанию: итог проходит `7z t`, строгую сверку списка/размеров, контрольную распаковку и per-file SHA-256, включая пустые каталоги. Dual дополнительно требует успешного `verify-worker.exe`. Streaming проверяет восстановленные байты через изолированный COM decoder `7z.dll`, не записывая их на диск; при недоступности worker используется Disk. Ошибка проверки не разрешает публикацию. Windows 10 runtime worker проверен; Streaming остаётся экспериментальным.
- Изменение входных данных во время поиска приводит к ошибке. Выход и временный каталог должны находиться вне входного дерева; символические ссылки не поддерживаются.
- Публикация использует durable journal, SHA-256 старых/новых выходов, backup и блокировку выходного каталога. Один файл заменяется атомарно; тома — последовательно с восстановлением. После аварии GUI предлагает восстановить прежний набор из `.ultraarch-output-*`; неизвестные каталоги и чужие изменённые выходы не удаляются. Это не атомарная публикация всего набора томов.

Профили `safe`, `deep` и `extreme` различаются числом проверяемых параметров. Матрица включает Store, LZMA2, PPMd и подходящие фильтры BCJ/BCJ2/Delta; `deep` и `extreme` также включают LZMA1, BZip2 и Deflate. `extreme` расширяет контексты LZMA1, PPMd до order 32 и 1536 МиБ, Delta до 32 и BCJ2 с отдельными параметрами потоков. Словари ограничиваются объёмом входа и оценкой памяти. Используется стандартный формат 7z; совместимость конкретных версий сторонних распаковщиков отдельно не проверялась.

Высокая энтропия не исключает сжатие. `--search fast|balanced|exhaustive` задаёт полноту поиска. Fast/Balanced сначала тестируют полные Store/LZMA2 baselines, затем sample-финалистов и соседние значения параметров лидера на полном входе. Delta сохраняет финалистов для разных контекстов; уточнение ограничено двумя раундами по восемь дополнительных кандидатов. Сохраняются семьи фильтров BCJ/BCJ2, расширения и целые небольшие PE. Sample — эвристика: лучший вариант может быть пропущен. Для входов <=2 MiB sample пропускается: Fast/Balanced сокращают полноразмерный турнир по семействам, Full сохраняет всю допустимую матрицу. `--adaptive` является alias Balanced; последний параметр режима имеет приоритет. `--goal size|speed --tolerance 1` выбирает минимальный размер либо наиболее быстрый успешный кандидат в заданном процентном допуске.

`--content exact|optimize` отделяет точные байты от оптимизации ресурсов. По умолчанию exact. Leanify/ECT запускаются только на приватных копиях; принимаются статические PNG/JPEG с совпадающими декодированными пикселями, сохранёнными цветом/ориентацией и меньшей LZMA2-стоимостью. Анимированные и другие изменённые форматы пока отклоняются. Неизменённые файлы overlay используют hard links при возможности; исходники инструменты не получают. Legacy `--preprocess` требует Extreme. Precomp/SREP не подключены: обратного восстановления нет.

Контракт данных: сохраняются относительные имена, содержимое и пустые каталоги. Ссылки/reparse и ADS отклоняются. ACL, владельцы, timestamp/NTFS security metadata не являются частью сохраняемого содержимого. Quota распаковки проверяется по listing до запуска, во время процесса watchdog с интервалом 100 ms и после завершения. Между опросами возможен временный выход за пределы лимита; это не жёсткая NTFS quota.

## Ресурсы и управление

Лимит `--ram` задаётся в MiB (8192 = 8 GiB). На Windows общий Job Object ограничивает **committed memory дочерних процессов**, а планировщик резервирует оценку памяти кандидатов. Лимит не включает память GUI и не является ограничением физической RAM всей системы. Ошибка подключения защиты не допускает незащищённого запуска.

`--workers` определяет число параллельных кандидатов. `--cpu-threads` задаёт бюджет потоков компрессии; автоматически используются обнаруженные физические ядра, до четырёх потоков на процесс. Это параметр 7-Zip, а не системная квота CPU. По умолчанию используется планировщик Windows без жёсткой affinity. `--affinity physical|sets|none` выбирает привязку или экспериментальные CPU Sets; для нескольких processor groups принудительные режимы отключены. Large Pages автоматически не активируются.

В текущем исходном коде `--cpu-limit 25` задаёт жёсткую квоту CPU дочернего Windows Job Object, `--disk-tasks 1` ограничивает число одновременно работающих кандидатов. Ограничение дисковых задач не означает квоту МБ/с. Общий Job Object охватывает параллельный поиск групп; память самого приложения остаётся за его пределами.

Extreme поддерживает LZMA1/LZMA2, PPMd до order 32, BZip2, Deflate, BCJ/BCJ2, Delta 1–32 и непрерывный solid. Группы ищут методы и собираются в стандартный 7z с несколькими блоками. Общий поиск остаётся конкурентом группового. `--no-grouping` отключает группы, `--grouping-only` оставляет группы и безопасный Store/исходный fallback. Эти ключи позволяют измерить вклад стратегий отдельно. Размер исходного совместимого 7z защищён кандидатом исходника в Exact без преобразования, пароля, SFX, томов или пользовательского solid.

Состояние улучшений и критерии измерения: [план по результатам Ultra7z](docs/compression-improvement-plan-2026-10-09.md), [дальнейшая оптимизация](docs/optimization-roadmap-2026-10-09.md). На одном сохранённом Test.7z новый Balanced дал 367 248 253 байта за 1436,508 с против 367 383 626 байт и 2850 с по GUI Ultra7z; все восстановленные файлы независимо проверены. Разные backend и одно наблюдение не доказывают общего превосходства на всех данных. Полные условия — в [отчёте прогресса](docs/compression-progress-2026-10-09.md). Сборки от 6 октября не содержат этих новых изменений.

Пауза прекращает выдачу новых задач; запущенные кандидаты продолжаются. «Пропустить» останавливает один активный кандидат. «Собрать лучшего» доступно после появления лидера, останавливает дальнейший поиск и собирает результат даже при паузе. Тайм-аут относится к каждому внешнему процессу. Общий бюджет времени прекращает поиск после появления первого успешного лидера; анализ и финальная проверка могут выйти за этот бюджет.

Проверенные лидеры и результаты сохраняются атомарно в `<temp>/sessions`. Повторный запуск с теми же данными, настройками и компрессором автоматически проверяет и восстанавливает совместимую сессию. После успеха её материалы удаляются; при отмене/ошибке проверенный лидер сохраняется. Пароль необходимо ввести заново: он не записывается в пресеты, checkpoint, таблицу и экспорт. На Windows пароль передаётся дочерним 7-Zip и verify-worker через приватный stdin, включая Unicode, кавычки и завершающий обратный слеш. NUL и переводы строк не поддерживаются. Пароль, введённый через собственный CLI-параметр `--password`, остаётся виден в аргументах самого приложения; ввод через GUI этого не требует.

Пресеты GUI хранятся в `%LOCALAPPDATA%\UltraArchStudio\presets`. Временный каталог по умолчанию — `.ultraarch_tmp` рядом с входом; для защищённых каталогов задайте доступный путь. Распаковка и предобработка могут потребовать значительно больше места, чем размер исходного архива.

## Windows: сборка и тесты

Нужны Visual Studio 2022 с Desktop development with C++, MSVC v143 x64, Windows SDK, CMake >=3.24, PowerShell 7. Зависимости находятся в `vendor`, утилиты в `bin`.

```powershell
pwsh -File ./tools/windows-build.ps1 -Configuration Release
pwsh -File ./tools/windows-build.ps1 -Configuration Debug -FaultTests
```

Команда собирает, тестирует, создаёт отдельные portable/developer ZIP и выполняет installed-package smoke из другого CWD в Unicode-пути. Переносить нужно пакет целиком: app, worker, bin, notices, SHA256SUMS. Developer дополнительно содержит тесты/скрипты и MSVC PDB при наличии. Инструменты не скачиваются и не обновляются автоматически. `bin/tool-manifest.json` фиксирует хеши, версии, provenance и лицензии; явный `--tools` не подменяется инструментами из PATH.

Установка Codex на Windows-ПК: [docs/windows-setup.md](docs/windows-setup.md). Обязательная runtime-приёмка и команды benchmark: [docs/windows-validation.md](docs/windows-validation.md). Состояние реализации и фактические проверки: [docs/implementation-status.md](docs/implementation-status.md).

`.github/workflows/windows.yml` собирает Debug/Release MSVC x64, запускает unit/integration suites на Windows и формирует Release artifact. Workflow начнёт выполняться после размещения проекта в GitHub.

## CLI

```powershell
./UltraArchStudio.exe --cli --input "D:\Data" --output "D:\Data.7z" --profile deep --ram 8192 --workers 2
./UltraArchStudio.exe --cli --input "D:\Data" --output "D:\Split.7z" --volume 1024 --password "your password" --encrypt-headers
./UltraArchStudio.exe --cli --input "D:\Dist" --output "D:\Dist.exe" --sfx
./UltraArchStudio.exe --cli --input "D:\Data" --temp "E:\Scratch" --cpu-threads 8 --timeout 3600 --time-budget 7200
./UltraArchStudio.exe --cli --input "D:\Data" --what-if
./UltraArchStudio.exe --help
```

Дополнительно: `--tools <dir>`, `--solid on|off|e|128m|...`, `--adaptive`, `--keep-all`, `--preprocess`, `--no-verify`. Последняя опция отключает только проверку кандидатов; итоговая проверка обязательна. CLI возвращает 0 после успешной публикации, 1 при ошибке, 2 при отмене. Вывод содержит фактические имена томов и суммарный размер. GUI What-if выполняется асинхронно и отменяется; для входного архива использует metadata listing без полной распаковки. `--report <file.json>` сохраняет диагностику без пароля. `--verifier disk|dual|stream` задаёт финальную проверку.

Горячие клавиши GUI: Ctrl+S — запуск, Space — пауза/возобновление очереди, Escape — запрос отмены. При вводе текста Space/Escape не управляют движком. Выключение после завершения опционально; есть кнопка отмены запланированного выключения. Закрытие работающего окна сворачивает его в tray.

## Разработка ядра

Поддерживаемый продукт — Windows. На macOS/Linux собирается только CLI/тестовый стенд ядра, без GUI и без подтверждения Windows Job Objects:

```sh
cmake -S . -B build-core -DCMAKE_BUILD_TYPE=Debug -DULTRAARCH_SANITIZERS=ON
cmake --build build-core --parallel 4
ctest --test-dir build-core --output-on-failure
```

Для integration suite нужен установленный `7zz`/`7z`. Windows-кросс-сборка доступна через `cmake/toolchains/mingw64.cmake`, если MinGW находится в PATH. Подробности изменений и выполненных проверок — `docs/history/2026-10-04-fixes.md`. Первоначальный аудит сохранён в `docs/history/2026-10-04-audit.md` как исторический документ.

Текущий этап: [реализация и доказательства](docs/roadmap-implementation-2026-10-09.md). `--lzma-dictionary <MiB>` задаёт максимум истории LZMA; фактический словарь ограничивается solid-потоком и RAM. `--similarity-groups` добавляет экспериментального конкурента в Extreme grouping, сохраняя исходные группы.
